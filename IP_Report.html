ABSTRACT

This project report presents the design and implementation of Career Connect, a full-stack integrated placement and recruitment platform designed to bridge the gaps between students (job seekers), interviewers (company representatives), and administrators (university placement cells). The system is built using a modern decoupled architecture comprising a React and Tailwind CSS v4 frontend built on Vite, and a Node.js Express backend using a PostgreSQL database managed via Sequelize ORM.

Career Connect replaces highly fragmented, manual workflows with an automated workspace. For students, it provides profile creation, resume uploading with parsed feedback, job discovery, and application submission. For interviewers, it facilitates job posting with multi-stage approval workflows, candidate tracking, and status transitions (shortlisting, interview scheduling, and selection). For administrators, it offers an unified moderation portal to control user lifecycle status and approve or reject job postings.

This document describes the structural specifications, schema designs, component architecture, engineering methodology, operational procedures, and verification protocols of the prototype. The resulting system demonstrates transactional integrity across key recruiting workflows while highlighting core development benchmarks, external constraints, and architectural pathways toward production scaling.

Keywords

Full-Stack Web Development, React, Tailwind CSS, Node.js, Express, PostgreSQL, Sequelize ORM, Relational Database Design, Role-Based Access Control (RBAC), Recruitment Automation.

Introduction to the project

Background

Traditional recruitment websites like LinkedIn or indeed.com serve broad global audiences but lack the hyper-localized, curated environments required by universities or dedicated enterprise programs. Educational institutes require tailored portals that support specific institutional guidelines, including:

  1. Academic Verification: Restricting student access based on registration codes, grade-point averages, or specific degree types.
  2. Corporate Vetting: A rigorous administrative approval hierarchy where employers must submit credentials for verification before posting vacancies.
  3. Structured Evaluation Pipelines: A linear funnel consisting of: applied → shortlisted→ interview scheduled → selected or rejected, which is visible to coordinators in real-time.

Recent advancements in single-page application (SPA) architectures and lightweight object-relational mapping (ORM) frameworks make it possible to construct custom portals rapidly. By utilizing React for a highly responsive, state-driven user interface and Node.js with PostgreSQL for robust transactional security, institutions can build and run their own proprietary placement ecosystems.

Problem Statement

In modern educational institutions and corporate recruiting systems, the process of aligning student profiles with industry opportunities remains highly fragmented. The sponsoring institution and corporate recruiters face several critical pain points:

  1. Inefficient Sourcing and Coordination: Placement cells rely heavily on email threads, manual spreadsheets, and physical notices to announce job listings, manage applications, and coordinate interviewer visits. This results in significant overhead, high data-entry error rates, and delayed communication.
  2. Lack of Transparency: Students frequently apply for jobs without visibility into their application state. Conversely, company interviewers suffer from a lack of integrated applicant tracking tools to easily review, shortlist, and transition candidates through different evaluation phases.
  3. Approval and Quality Control Bottlenecks: Placement coordinators must verify that every company representative is legitimate and that every job post meets university and industry standards. Without a centralized administration dashboard, verifying corporate users and moderating postings becomes slow and error prone.

From the sponsoring organization’s perspective, the objective is to build a unified, secure portal that facilitates communication, establishes strict role-based data isolation, and scales to thousands of concurrent users during high-intensity placement drives.

Methods and Design Approach

The development team executed a rigorous, database-first software engineering cycle divided into five distinct phases, emphasizing clear structural isolation and system stability.

Figure . Application design flowchart

Sequence of Problem-Solving Steps

  1. Relational Database Design: We began by defining a comprehensive relational model. Using entity-relationship modeling, we mapped out distinct entities for Users, Profiles, Resumes, Jobs, Applications, Interviews, Resources, and Approval Requests.
  2. Object-Relational Mapping (ORM) Integration: To avoid writing brittle raw SQL queries, we integrated Sequelize. This allowed us to establish migrations, enforce table constraints programmatically, and build clean 1:1 and 1:N associations.
  3. Backend API Routing and Middleware: We constructed an Express application organized around modular routers. To enforce role-based access control, we implemented a custom authentication middleware that decodes JSON Web Tokens (JWT) and validates the user’s role (ADMIN, INTERVIEWER, STUDENT) before passing requests to controller endpoints.
  4. Frontend Architecture: We selected Vite as the build tool for React to ensure instant hot-module replacement. We structured the frontend using a standard layout wrapper containing localized sub-pages (Dashboards, Resume Builders, Job Explorers, and Admin Moderation Portals) styled with Tailwind CSS v4 and animated using Framer Motion.
  5. Continuous Verification and Seed Testing: To mimic production conditions, we created database seed scripts that populate the local PostgreSQL database with standardized profiles, mock job roles, and candidates, allowing us to perform rigorous end-to-end user-flow validation.

Software and Hardware Requirement Specification

This section outlines the software methodologies, environment setups, and configuration settings required to develop, run, and scale Career Connect.

Methods

Development was executed under the Agile Iterative Software Engineering Model. Rather than building the client and backend simultaneously in an uncoordinated fashion, we followed a strict, component-driven approach:

  • API First: The server endpoints, request bodies, and JSON responses were fully documented before client components were constructed.
  • Decoupled Deployment Readiness: The client is prepared to build into static assets (index.html, /assets/index-xxx.js), meaning the frontend can be deployed onto CDN edges, while the backend runs as a decoupled node container talking to a remote RDS or local PostgreSQL cluster.

DATABASE ANALYZING, DESIGN, AND IMPLEMENTATION

Database Analyzing

Placement systems handle high-frequency concurrent operations during placement drives (hundreds of students applying to job roles in minutes). A relational model was selected to ensure:

  1. Referential Integrity: An application cannot point to a deleted resume or job position.
  2. Transaction Security (ACID): Candidate status updates and job listings happen reliably without danger of partial write states.
  3. Optimized Query Structuring: Fast lookup filters using job tags or user ID constraints.

Relational Database Design

Tables are fully mapped using PostgreSQL constraints. Primary Keys are designated as autoincrementing integers (SERIAL), and relationships enforce foreign key constraints (REFERENCES) with cascading deletion triggers (ON DELETE CASCADE / ON DELETE SET NULL) to protect system integrity.

  1. users Table Schema

id: SERIAL PRIMARY KEY

name: VARCHAR(255) NOT NULL

email: VARCHAR(255) UNIQUE NOT NULL

password_hash: VARCHAR(255) NOT NULL

role: user_role Enum ('ADMIN', 'INTERVIEWER', 'STUDENT')

status: VARCHAR(50) DEFAULT 'active'

company_name: VARCHAR(255) NULL

created_at: TIMESTAMP WITH TIME ZONE

updated_at: TIMESTAMP WITH TIME ZONE

  1. profiles Table Schema

id: SERIAL PRIMARY KEY

user_id: INTEGER REFERENCES users(id) ON DELETE CASCADE

created_at / updated_at: TIMESTAMP WITH TIME ZONE

  1. resumes Table Schema

id: SERIAL PRIMARY KEY

user_id: INTEGER REFERENCES users(id) ON DELETE CASCADE

title: VARCHAR(255) DEFAULT 'My Resume'

file_url: VARCHAR(255) NULL

parsed_content: TEXT NULL

ai_score: INTEGER NULL

ai_feedback: TEXT NULL

created_at / updated_at: TIMESTAMP WITH TIME ZONE

  1. jobs Table Schema

id: SERIAL PRIMARY KEY

title: VARCHAR(255) NOT NULL

tags: TEXT[] DEFAULT ARRAY[]

id: SERIAL PRIMARY KEY

student_id: INTEGER REFERENCES users(id) ON DELETE CASCADE

  1. interviews Table Schema

id: SERIAL PRIMARY KEY

Centralized Model Associations Index (/server/models/index.js)

Establishes references, indices, and foreign keys across all Sequelize entities:

const User = require('./User');

const Job = require('./Job');

// 1:1 User -> Profile mapping

User.hasOne(Profile, { foreignKey: 'user_id' });

Profile.belongsTo(User, { foreignKey: 'user_id' });

// 1:N User -> Resume mapping

User.hasMany(Resume, { foreignKey: 'user_id' });

8.3. Core Express Server Configuration (/server/server.js)

Configures middleware registry, handles register/login security logic, and boots the backend:

require('dotenv').config();

const express = require('express');

const cors = require('cors');

const sequelize = require('./config/db');

const { User } = require('./models');

const bcrypt = require('bcrypt');

const jwt = require('jsonwebtoken');

const jobsRouter = require('./routes/jobs');

const applicationsRouter = require('./routes/applications');

const resumesRouter = require('./routes/resumes');

const adminRouter = require('./routes/admin');

const app = express();

const port = process.env.PORT || 5000;

app.use(cors());

app.use(express.json());

// Users endpoint for testing & Admin moderation

app.get('/api/users', async (req, res) => {

try {

const users = await User.findAll({ attributes: ['id', 'name', 'email', 'role', 'status', 'created_at'] });

res.json(users);

} catch (error) {

res.status(500).json({ error: 'Internal server error' });

}

});

// Update user status (Admin moderation)

app.put('/api/users/:id/status', async (req, res) => {

try {

const { status } = req.body;

const user = await User.findByPk(req.params.id);

if (!user) return res.status(404).json({ error: 'User not found' });

user.status = status;

await user.save();

res.json(user);

} catch (error) {

res.status(500).json({ error: error.message });

}

});

// Register

app.post('/api/auth/register', async (req, res) => {

try {

const { name, email, password, role } = req.body;

const userRole = role || 'STUDENT';

const hashedPassword = await bcrypt.hash(password, 10);

const user = await User.create({ name, email, password_hash: hashedPassword, role: userRole });

res.status(201).json({ id: user.id, name: user.name, email: user.email, role: user.role });

} catch (error) {

res.status(500).json({ error: error.message });

}

});

// Login and JWT issuance

app.post('/api/auth/login', async (req, res) => {

try {

const { email, password } = req.body;

const user = await User.findOne({ where: { email } });

if (!user) {

return res.status(401).json({ error: 'Invalid email or password' });

}

const isMatch = await bcrypt.compare(password, user.password_hash);

if (!isMatch) {

return res.status(401).json({ error: 'Invalid email or password' });

}

const token = jwt.sign({ id: user.id, role: user.role }, process.env.JWT_SECRET || 'secret123', { expiresIn: '1d' });

res.json({ token, user: { id: user.id, name: user.name, email: user.email, role: user.role } });

} catch (error) {

res.status(500).json({ error: error.message });

}

});

app.use('/api/jobs', jobsRouter);

app.use('/api/applications', applicationsRouter);

app.use('/api/resumes', resumesRouter);

app.use('/api/admin', adminRouter);

sequelize.sync({ alter: true }).then(() => {

app.listen(port, () => {

console.log(`Server running on port ${port}`);

});

});

LIMITATIONS

Although Career Connect successfully facilitates core recruitment pipelines, this initial version includes several system mockups and engineering limitations:

Mocked AI Scoring: The resume feedback parser is currently mocked, returning a generated random rating score between 80% and 100% instead of integrating direct machine learning parsing models.

Lack of PDF Viewer: Recruiters review applicant listings but must download resumes manually. An integrated client-side web PDF rendering viewport does not yet exist.

Incomplete Interview Details: Recruiters can transition statuses to "Schedule Interview," but the portal lacks modal interfaces to let them select dates/times, input Google Meet paths, or attach schedule coordinates.

Nodemailer SMTP Stubs: Email notifications via NodeMailer are restricted to mock console outputs (via a // TODO backend structure). Automated emails are not dispatched to real user inboxes.

No Admin Search Filters: The Admin Dashboard lists user records and jobs in raw tables but lacks live text search boxes or filtering queries, complicating moderation in large-scale installations.

CONCLUSION

Career Connect achieves its primary objectives. The application establishes a secure, unified placement environment that completely decouples front-end interface rendering from relational backend schemas. By using standard PostgreSQL indexes and Sequelize transactions, the system protects placement data against synchronization conflicts.

The custom JWT verification middleware effectively isolates access rights between Students, Recruiters, and Administrators. While certain services (like AI ratings and email triggers) are mocked in the current prototype, the database relations, authentication flows, and placement pipelines are fully functional and ready to support university placement coordination.

In-Browser PDF Rendering: Integrate pdfjs-dist libraries inside the recruiter tracking tables, letting company representatives view applicant documents on the fly without making local downloads.

Calendar Synchronizer: Connect the Interview scheduler with the Google Calendar API. Transitioning candidate applications to "Interview Scheduled" will automatically spin up Google Meet links and save events to both the recruiter's and student's calendars.

Active SMTP Services: Hook the NodeMailer utility to AWS Simple Email Service (SES) or SendGrid APIs to trigger real-time, automated verification codes and interview alerts.

Redis Memory Cache: Implement a Redis layer to cache standard job query filters (e.g. location, salary, tags), protecting the PostgreSQL backend database from read spikes during intensive campus placement drives.
